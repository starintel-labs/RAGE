* Problem

StarIntel needs a low-cost long-term archive that is also recoverable, auditable, and safe under partial failure. The operator additionally wants lifecycle/retention configuration in trusted =init.lisp=, policy overrides per target/type from server-side actors/plugins, durable commercial settlement, and an auto-scale actor for Star Server and CouchDB with a Jev-shaped RSI adviser.

The system must not conflate:

- process/add-on lifecycle with data-retention lifecycle;
- backup upload with backup verification;
- archive custody with billing authority;
- model advice with infrastructure authority;
- fast Star Server concurrency changes with slow CouchDB topology changes.

* External Evidence

Retrieved 2026-09-20.

- Apache CouchDB 3.5 backup documentation states CouchDB replication is the simplest backup approach and also states that =.couch= database files can be copied while CouchDB is running because storage is append-only. It recommends backing up secondary indexes before main database files and permits storage snapshots when the filesystem is quiesced as required: https://docs.couchdb.org/en/stable/maintenance/backups.html
- CouchDB =_changes= is suitable for synchronization but can redeliver entries, so consumers must be idempotent: https://docs.couchdb.org/en/stable/api/database/changes.html
- Akamai/Linode Object Lock must be enabled when the bucket is created and cannot be retrofitted through ordinary Cloud Manager/Linode API flows. A bucket without Object Lock must not be called WORM/immutable: https://techdocs.akamai.com/cloud-computing/docs/protect-logs-in-object-storage
- Akamai documents COMPLIANCE Object Lock as preventing deletion before retention expiry and GOVERNANCE as bypassable only with special permission/explicit bypass: https://techdocs.akamai.com/cloud-computing/docs/data-protection
- TypeSafe describes Jev as a System One model: structured state in, typed probabilistic decisions out, trained for calibrated decisions. It is an adviser shape, not an unrestricted text/action generator: https://typesafe.ai/blog/introducing-system-one-models-and-jev

* Core Package: =:starintel-archive=

The core package owns data and policy semantics, not service startup.

Required public concepts:

- =archive-policy=
- =policy-selector=
- =resolved-policy=
- =backup-manifest=
- =archive-artifact=
- =custody-receipt=
- =verification-receipt=
- =retention-decision=
- =archive-backend= protocol.

Required invariants:

1. Artifact IDs are content/policy-derived and idempotent.
2. A successful PUT is not durable custody.
3. A remote object is not verified until stat/readback/checksum policy succeeds.
4. A backup is not restore-verified until a disposable restore succeeds.
5. Hot/source eviction requires the resolved policy plus verified custody/restore proof.
6. Unknown policy is fail-closed.
7. Credentials are never serializable members of manifests or receipts.

* Data Lifecycle Policy

Archive lifecycle means retention/custody lifecycle, not Common Lisp add-on lifecycle.

** Default policy

Initial safe defaults:

- archive sync: hourly;
- full recovery snapshot: daily;
- local fast-restore retention: 14 days;
- remote cold retention: 365 days;
- restore verification: weekly/sample at minimum;
- minimum custody before any possible eviction: verified remote;
- automatic source deletion: false;
- legal/case hold: absolute blocker for expiration.

** Trusted configuration

Trusted =init.lisp= may configure global values and narrower selectors.

Conceptual interface:

#+begin_src lisp
(star.archive.policy:configure-defaults
 :snapshot-every :hourly
 :full-snapshot-every :daily
 :local-retention-days 14
 :remote-retention-days 365
 :minimum-custody :verified-remote
 :restore-verify-every-runs 7
 :delete-source-after-archive nil)

(star.archive.policy:for-dtype "observation"
 :remote-retention-days 730)

(star.archive.policy:for-target "target:case-123"
 :pinned t
 :remote-retention-days 2555)
#+end_src

** Actor/plugin policy injection

Server-side actors/plugins may inject bounded facts such as:

#+begin_example
archive_requested_retention(target-123, long).
archive_hold(target-123, court_case_42).
archive_class(dtype_observation, evidence).
#+end_example

Actor facts are proposals. The server resolves them against operator policy and capability context. A less-privileged source cannot shorten minimum retention, disable verification, remove a hold, or expand tenant/dataset scope.

* Backup Execution

** Job A: couch-snapshot

One-shot, fenced, deterministic snapshot creation.

Capture:

- CouchDB database files and required system databases;
- required configuration excluding secrets;
- database inventory;
- update sequence/capture boundary;
- file sizes;
- SHA-256 digests;
- package/core version and policy digest.

Preferred implementation may use a storage-level snapshot when available, otherwise copy CouchDB files following official backup ordering. A crash/interruption produces an incomplete run that archive-sync refuses.

** Job B: archive-sync

Consumes only complete snapshot manifests.

Stages:

1. write immutable local S3 object;
2. update TEK9/star-git archive/catalog state;
3. write Linode cold object;
4. stat/readback/checksum;
5. register custody receipt;
6. run disposable restore according to policy;
7. register restore-verification receipt;
8. evaluate retention eligibility.

Each stage has its own durable status so restart resumes rather than repeats ambiguous work.

* Local S3

Local S3 is a dedicated backup service, not LocalStack. It is optimized for fast restore and low cost and must use a storage failure domain distinct from the CouchDB data volume.

The exact S3 server package is an Infra implementation choice gated by:

- NixOS reproducibility;
- S3 compatibility required by the archive backend;
- immutable/object-version semantics where supported;
- simple restore/export;
- bounded memory/CPU;
- durable storage on the large/local archive datastore.

Local S3 is never the only disaster-recovery copy.

* Linode Cold Tier

Operator destination:

#+begin_example
bucket   = star-archive
endpoint = star-archive.us-ord-10.linodeobjects.com
#+end_example

Preflight checks versioning/Object Lock. If Object Lock is not enabled, =star-archive= remains a remote backup copy but cannot satisfy a =WORM= custody requirement. A new lock-enabled bucket is required for WORM semantics because Object Lock must be enabled at creation.

Use least-privilege write credentials for the normal job. Administrative bucket configuration and retention policy changes use a separate privileged path.

* Restore Safety

Durability is defined by recovery evidence.

A restore drill creates a disposable CouchDB restore target and verifies:

- expected databases exist;
- expected document counts/inventory within policy;
- sampled or full document digests;
- attachment/content checks where applicable;
- system/config compatibility;
- target can be opened/read by the pinned CouchDB version.

Failure blocks retention GC and raises archive-degraded state.

** Plan

** Settlement

Every eligible provider call follows:

#+begin_example
quote -> reserve -> execute -> commit | refund
#+end_example

Reservation is concurrency-safe and idempotent. Provider final cost, included-budget debit, PAYG cost, markup, and customer charge are distinct ledger values.

Platform-required backup/archive/restore verification is platform COGS by default. It does not consume a tenant's USD 15 included API budget unless an explicit product entitlement classifies that request as customer-billable. Customer-triggered premium export/restore may be billable under a separate entitlement.

Biz #163 continues to hard-exempt platform owner/admin/operator customer charges while recording real COGS.

* Auto-Scale Actor

** Generic server contract

=star.auto-scale= is a bounded supervised actor that emits typed scaling intents. It does not directly call provider APIs from a model callback.

Closed actions:

#+begin_example
hold
scale-server-out
scale-server-in
scale-couch-out
scale-couch-in
rebalance-couch
throttle
escalate
#+end_example

Every decision carries:

- magnitude;
- urgency;
- confidence;
- evidence window;
- policy/model generation;
- decision ID;
- cost delta estimate;
- fencing generation.

** Separate control loops

Star Server worker concurrency is a comparatively fast reversible loop.

CouchDB node/shard/rebalance actions are a slow topology loop. Scale-in is blocked during unsafe health, replication backlog, disk pressure, unverified rebalance, or policy cooldown.

** Deterministic fallback

Model outage never disables capacity safety. A deterministic threshold/hysteresis controller remains available and may only issue actions allowed by the same Prolog policy.

* Jev-Shaped Decision Adviser

Jev is used as the interface model, not as authority.

State includes:

- queue depth/backpressure;
- latency percentiles;
- utilization;
- CouchDB read/write/replication/compaction health;
- disk growth;
- current capacity;
- prior changes/cooldowns;
- COGS/budget;
- recent SLO violations.

Typed questions include:

- action choice;
- magnitude score;
- urgency score;
- probability that acting now violates a safety/SLO constraint;
- confidence/uncertainty.

The interface is provider-neutral =autoscale-decision/v1=. TypeSafe Jev may serve as an external adviser while available; a later custom local model can implement the exact same contract through =llm.starintel.actor=. No design assumes TypeSafe exposes custom fine-tuning until documented.

* Bounded RSI

RSI is offline candidate evolution, never live self-modification.

#+begin_example
immutable trajectories
      |
      v
objective scoring
      |
      v
candidate proposal/training/calibration
      |
      v
held-out replay
      |
      v
adversarial failure suite
      |
      v
shadow
      |
      v
bounded canary
      |
      v
Prolog promotion gate
      |
      v
operator approval when topology/policy affected
      |
      v
promote + retain rollback artifact
#+end_example

A candidate cannot edit or approve its own safety bounds. Training data excludes credentials, secrets, and tenant document payloads.

Objectives are multi-dimensional: latency/SLO, availability, backpressure, safe CouchDB topology, total COGS, scaling churn, and rollback frequency. Cost reduction cannot compensate for broken durability or availability.

* Cross-Repo Invariants

1. No backup deletion on mere upload success.
2. No hot/source eviction without resolved policy and required custody/restore proof.
3. No billing state is authority for backup correctness.
4. No model decision is infrastructure authority.
5. No self-modifying RSI process can promote itself.
6. No secret appears in archive manifest, model trajectory, or billing event payload.
7. Every network/provider mutation is idempotent or fenced.
8. Every destructive action has a generation/policy digest and audit event.
9. Operator/admin billing exemption does not hide COGS.
10. Remote cold storage is cost-optimized, but local restore and remote disaster copies are distinct failure domains.
